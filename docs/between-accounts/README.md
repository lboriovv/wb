# Перенос счёта: пружинный отклик пустого поля

Спецификация прототипа «Между счетами · переход». Исходное состояние: накопительный счёт выбран в «Откуда», «Куда» пусто. Обратное направление работает симметрично.

## 1. Анимация

При выборе счёта, уже стоящего в другом поле, он переносится в выбранное поле, прежнее поле становится пустым и один раз пружинит по горизонтали; перенос сопровождают три коротких тактильных удара.

![Предпросмотр переноса счёта](media/between-accounts-transition-preview.gif)

[Запись экрана 1×](media/between-accounts-transition-1x.mp4) · [Тот же фрагмент 0,25×](media/between-accounts-transition-quarter-speed.mp4). Видео записано в iPhone Simulator; тактильную отдачу в нём нельзя почувствовать, поэтому её параметры описаны ниже отдельно.

## 2. Таймлайн

Время отсчитывается от выбора в шите счёта, который уже находится в противоположном поле.

| От выбора | Событие | Хаптик |
| ---: | --- | --- |
| 0 мс | Счёт назначается выбранному полю, прежнее поле очищается, шит закрывается с `.snappy(duration: 0.2)`. | Нет отдельного удара выбора. |
| 180 мс | Начинается один горизонтальный шейк освободившейся плашки. | `.rigid`, интенсивность `0.8` |
| 260 мс | Шейк продолжается. | `.rigid`, `0.8` |
| 340 мс | Шейк продолжается. | `.rigid`, `0.8` |
| 640 мс | Шейк завершён, плашка находится в исходной позиции. | — |
| 660 мс | Анимационный прогресс сбрасывается без видимого движения. | — |

При выборе **другого** счёта он просто назначается выбранному полю: противоположное поле не очищается, шейк и серия из трёх ударов не запускаются.

## 3. Детали реализации

**Состояние.** Если ID выбранного счёта совпадает с ID в противоположном поле, этот счёт назначается полю, по которому открыли шит, а противоположное поле очищается. Пружинит только что опустевшее поле. Сам счёт не должен одновременно остаться в обоих полях.

**Микроотклик пустого поля.** Иконка увеличивается максимум примерно до `1,049×` через 133 мс после начала шейка и возвращается к `1×` примерно через 280 мс. Это изменение относится только к пустой плашке; сумма и другая плашка не дрожат.

**Хаптик.** Три одинаковых `UIImpactFeedbackGenerator(style: .rigid)` с `impactOccurred(intensity: 0.8)` через 80 мс друг от друга, в моменты из таймлайна. Не добавлять четвёртый удар. Тактильный ритм проверить на физическом iPhone: симулятор воспроизводит только картинку.

## 4. Кривые Безье

Вся пустая плашка движется только по `translationX`. Траектория трижды меняет направление, поэтому одной `cubic-bezier` недостаточно: нужны шесть последовательных этапов без паузы и второго импульса.

![Шесть кривых Безье с координатами](bezier-curves.png)

В [таблице этапов](bezier-points.md) указаны время, смещение и нормализованные координаты `cubic-bezier(x1, y1, x2, y2)` для каждого участка. [JSON](bezier-points.json) содержит те же параметры для импорта; схема доступна и в [SVG](bezier-curves.svg). Прототип пока вычисляет траекторию формулой в коде, а эти кривые воспроизводят её с максимальным расхождением около `0,13 pt`. Для передачи разработчикам используйте кривые как единую спецификацию движения.

## Проверка

- Выбор того же счёта в «Куда» освобождает «Откуда»; выбор в обратном направлении освобождает «Куда».
- На освободившемся поле ровно один шейк за 460 мс и ровно три равных удара через 80 мс.
- Поле и счёт после анимации не меняют назначение ещё раз; повторной волны нет.
- Запуск прототипа: `-demoOpen groups-work/between-accounts-transition`.

Исходная реализация: `WBSandbox/Screens/UniQRScreen.swift` (`selectTransferAccount`, `playSlotAttention`, `UniQRPremiumAttentionEffect`).
